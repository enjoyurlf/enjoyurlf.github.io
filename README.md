# 色块扫雷 · Vue 逻辑求解工作台

基于两张图片还原的可编辑单星放置谜题，支持自定义棋盘、增减颜色和本地精确求解。使用 Vue 3、Composition API、TypeScript 与 Vite，无 Python 后端、无 CDN、无远程上传。

> 请通过 HTTP 服务打开网页，不要直接双击构建后的 HTML。求解依赖 Web Worker。棋盘进度保存在当前浏览器、当前站点的 localStorage 中；重要棋盘请导出 JSON 备份。

## 启动网页

前置环境：Node.js 20.19+（推荐 22+）和 pnpm 11+。uv 可以用于辅助 Python 分析，但不是运行网页的依赖。

在终端中执行：

```powershell
cd E:\ai\touhou\mine-color-solver
pnpm install
pnpm dev --port 5173 --strictPort
```

打开 http://127.0.0.1:5173 。

生产构建与本地预览：

```powershell
pnpm build
pnpm preview --port 5173 --strictPort
```

预览服务器不自动重新构建，修改源码后需要再次执行 `pnpm build`。

## 生成随机唯一解地图

打开 http://127.0.0.1:5173/#/generator ，或点击顶部“随机出题”。首次打开自动生成一张 7×7 地图。

1. 设置“棋盘边长”和“颜色数量”，点击“生成随机地图”。支持 1×1、4×4 至 16×16；颜色数量必须与边长相等。修改边长时，原本匹配的颜色数会同步调整，也可以单独输入颜色数量；不匹配时提示原因并禁用生成。
2. 默认只显示随机色块，隐藏雷位。点击“查看答案”即可显示所有地雷及其行列坐标；再次点击“隐藏答案”收起。
3. 再次生成会换一张题目，并自动隐藏答案。修改参数立即清除旧地图，取消旧的生成任务。
4. “导出题目”保存没有答案标记的 JSON；可在“编辑求解”页导入，继续涂色修改或验证答案。离开随机页或刷新会重新出题，要保留当前题目请先导出。

生成器先随机选择合法雷位，再生长随机色块。每次接受色块变化前，都用无手动标记的棋盘检验唯一性；若发现多解或搜索未完成，就拒绝此次变化。生成成功的地图确实只有一个解，而不是仅挑选了某个可行方案。随机生成的同色区域保持上下左右连通，但不保证难度一致、区域面积相等或雷位等概率。1×1 只有一种布局。

生成在后台 Worker 中运行，可取消；计算预算限制色块扩展次数，保留最后一个经过完整唯一性验证的地图，不会把截断搜索结果当作唯一解。2×2、3×3 在当前规则下无解，因此无法出题。

## 修改棋盘和颜色

| 操作 | 方法 | 注意事项 |
| --- | --- | --- |
| 修改边长 | 输入 1–16 的整数，点击“新建棋盘” | 方形棋盘；重置色块与标记，可撤销。默认每行填一种颜色 |
| 增加颜色 | 点击区域颜色旁的“添加” | 调色盘最多 32 色；涂到棋盘才算实际使用 |
| 删除颜色 | 点击对应颜色的垃圾桶按钮 | 使用中的格子合并到选中的其他颜色；若删除选中色，合并到第一种其他颜色。可撤销 |
| 修改显示色 | 点击颜色条右侧的小圆点 | 区域按编号区分；相同 RGB 不会自动合并区域 |
| 改变格子区域 | 选择“涂色”、选择颜色，点击或拖动棋盘 | 鼠标右键格子可取色；支持触摸拖动 |
| 增加已知信息 | “标雷”标记已知雷，“排除”标记安全格 | 两种标记均参与约束求解 |
| 删除标记 | “擦除”单格，或“清除标记”全部清除 | 不改变底层色块颜色 |
| 撤销/重做 | 工具栏按钮或 Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y | 一次连续拖动作为一个操作；保留最多 80 步历史 |
| 保存与分享 | 页面右上角导出/导入 JSON | 包含尺寸、区域颜色、矩阵、手动标记；导入校验格式 |

新建棋盘会补足需要的颜色，保留已有调色信息；未使用的调色盘颜色不参与“每色一雷”。原图可通过“恢复原图”重新载入。

## 三条规则和原图答案

这不是需要周围雷数的传统数字扫雷，而是“每区一枚”的单星放置谜题。图片中的狗狗可视为需要放置的地雷：

1. 每种实际使用的颜色恰好一枚地雷。
2. 每行、每列恰好一枚地雷。
3. 地雷不能八方向相邻，上下、左右、斜角都不允许。

由规则 1 与 2 可知，N×N 棋盘必须实际使用 **N 种颜色**，总雷数为 N。2×2 与 3×3 即使颜色数量正确，也会因不相邻约束无解。相同颜色即使不连通，依旧是同一个区域；没有额外加入“颜色必须连通”限制。

原图独立枚举全部 7!=5040 个列排列后，恰好一个解。坐标均从左上角起，行列从 1 开始：

| 行 | 列 | 颜色 |
| --- | --- | --- |
| 1 | 4 | 青蓝 |
| 2 | 7 | 莓红 |
| 3 | 5 | 浅黄 |
| 4 | 2 | 赭黄 |
| 5 | 6 | 森林 |
| 6 | 3 | 柔紫 |
| 7 | 1 | 浅粉 |

## 理解求解结果

- **唯一解**：展示全部确定雷位和安全格。
- **多解**：“推理结果”只标记所有解共有的雷位、所有解均不出现的安全格，其他候选格显示圆点；“方案预览”查看某个具体合法方案，预览不代表确定答案。
- **无解**：已穷尽搜索，当前颜色分区和手动标记不存在合法布局。
- **输入冲突**：实际颜色数不符，或手动雷违反行、列、颜色、不相邻约束。
- **预算截断**：达到 10,000 个解或 1,000,000 个节点后停止，不宣称唯一、不根据部分统计认定必然安全或必然雷。可添加已知标记缩小搜索范围。

“原始色块”仅隐藏自动推断，手动标记仍显示。调整色块或标记后旧结果立即失效；自动求解开启时，防抖后启动新的 Worker，并终止旧搜索，避免旧答案覆盖新棋盘。

## 常见问题

- **棋盘显示“需要 N 色”**：检查实际涂色区域数量；只增加调色盘颜色不会增加棋盘区域数。
- **删色后无解**：删除会合并区域，可能破坏原谜题。撤销后重新划分颜色。
- **颜色改成相同色却仍算两种**：区域由编号确定，显示色仅用于外观。用涂色或删除合并来真正合并。
- **刷新丢失编辑**：浏览器禁用存储、清理站点数据、无痕模式、端口变化都可能影响本地保存，建议导出备份。
- **直接打开 HTML 求解失败**：Worker 需要 HTTP 服务，使用开发服务器或生产预览。
- **Windows 受限环境中构建报告 `spawn EPERM`**：Vite、esbuild、浏览器测试需要子进程管道；在允许相应操作的终端中运行。项目采用 hoisted 依赖布局以兼容虚拟化 Windows junction 的环境。
